How It Works

Two Engines, Working on Their Own Terms

One offchain pipeline that runs every block, on every node. A separate set of on-chain hooks that run automatically, as part of normal block and session execution. Neither waits for the other.

Before We Go Deeper

What Is an Affidavit?

A signed, voluntary declaration - an author states the election weight they want considered for the upcoming session. It isn’t a vote and it doesn’t move any value; it’s a claim, backed by a disposable signing key, that gets checked once by the election adapter and then cleared.

Off-Chain · Every Block

All four routines below run inside one offchain_worker call - independently, on every node.

one offchain_worker() call
01

Init Key

Bootstraps an active affidavit key if none exists yet - the first thing every block checks.

02

Try Election

Attempts the election the moment its window opens. Already run this round? It no-ops safely.

03

Declare Affidavit

Submits this round’s declared weight for N+1 - and stages a fresh key for N+2 in the same transaction.

04

Rotate Key

Confirms the N+2 key is finalized and fork-safe before treating it as the active one.

A Note on Session Numbering

What N, N+1, and N+2 Actually Mean

N

The session running right now. Contribution points accrue here, block by block.

N+1

The session being decided. The declared weight, the signing key that authorizes it, and the election result itself all target exactly one session ahead - nothing looks further than this for the actual outcome.

N+2

Not a second election. It’s how far ahead the signing key is staged. The moment Declare Affidavit succeeds for N+1, a fresh key is already being registered for N+2 - confirmed and fork-safe (that’s Rotate Key’s job) before the current key is ever spent.

At any moment, exactly one election is in flight, targeting exactly one session ahead. N+2 is security bookkeeping running one step ahead of it - not a longer lookahead.

On-Chain · Automatic

These run as part of normal block and session execution - no offchain worker involved.

05

Author Participation

pallet_session activates the elected set once the new session begins. They produce blocks and are watched for offences, for the whole session.

06

Contribution Tracking

Every block, on_initialize credits that block’s author - via pallet_authorship - with one point in the current session’s tally.

07

Settlement

Rewards

end_session pays out accumulated points for the closing session - once, on schedule.

Penalties

Triggered by OnOffenceHandler the instant an offence is reported - any time, on its own trigger.

08

Next Election

new_session reveals the result already computed off-chain; start_session advances CurrentSession and the whole cycle repeats.

Election Engine

Flexible Elections. Your Rules.

Chain Manager provides a pluggable election engine that selects the authors for the next session. It handles eligibility, candidate preparation, author selection, and result processing - while letting you define the actual election logic.

01

Check Eligibility

Determine whether the election can run, based on timing, runner authorization, minimum candidates, and other runtime-defined conditions.

02

Prepare Candidates

Collect eligible candidates from AuthorAffidavits and attach their declared election weights.

03

Elect Authors

Run the configured algorithm to select authors for the next session - the runner who submits the winning call earns bonus points.

04

Handle Result

Process the outcome and trigger the matching hook - ElectedInstance on success, ElectionAttemptFailed otherwise.

05

Reveal Authors

Expose the elected authors for the current period via the inspect_elects extrinsic.

Pluggable by Design

Affidavit Model

Self-Declared Weights. A Fairer Election.

Chain Manager lets authors voluntarily submit affidavits declaring their desired election weight for the upcoming session. Affidavits are optional, ephemeral, and consumed by the election process - giving your runtime a flexible way to factor in author intent.

01

Check Eligibility

Confirm the author has already called validate and holds an active affidavit key for the upcoming session.

02

Generate Affidavit

Create the affidavit, declaring an election weight of self-stake plus backing.

03

Submit Affidavit

File it within the open submission window via declare - the same transaction also stages a fresh signing key for the round after.

04

Rotate Key

The freshly staged key must be confirmed finalized and fork-safe before it becomes the one used for the next declaration.

05

Store for Election

Held in AuthorAffidavits, keyed by session and author, bounded by MaxAffidavitWeights.

06

Consumed by Election

Read by the election adapter during candidate preparation - never mutated by it.

07

Cleared After Use

Session-scoped storage that doesn't carry forward once the session ends.

Voluntary

Authors choose whether to submit an affidavit.

Time-Bound

Filed only within the automatically-timed submission window.

Ephemeral

Session-scoped, and cleared once the session ends.

Author-Relayed

Filed with a disposable key, never the author's stash or authority key.

Runtime-Read

Read by whatever election logic the runtime provides - never owned by Chain Manager.

Timing Windows

The Right Action. At the Right Time.

Chain Manager operates within well-defined time windows to keep the runtime predictable. Affidavit filing and the election itself share one overlapping window - while penalties, deliberately, follow no window at all.

One Session
01

Idle

No affidavit or election activity yet - the session has just begun.

0–20%
02

Affidavit Only

Authors may file affidavits declaring their election weight.

20–50%
03

Affidavit + Election

Filing stays open while the election itself runs, side by side.

50–80%
04

Settlement

Filing closes; rewards and routine settlement take over.

80–100%

Penalties - No Window

Triggered whenever an offence is reported, independent of every phase above. The one deliberate exception to this whole schedule.

Anytime
start_affidavit = session_start + (AffidavitBeginsAt × avg_session_length)
end_affidavit   = session_start + (AffidavitEndsAt   × avg_session_length)
start_election  = start_affidavit + (ElectionBeginsAt × (end_affidavit − start_affidavit))
end_election    = end_affidavit
Percentage-Based

Windows scale with average session length, not fixed block numbers.

Automatic

No extrinsic opens or closes a window - the runtime just checks the current position.

Cooldown-Protected

finality_after and finality_ticks delay any offchain action until it’s safe.

Self-Clearing

Session-scoped storage resets naturally - nothing needs to be swept by hand.

Contribution & Rewards

Every Block Counted. Every Author Paid.

Every block, the author who produced it earns a point. Every session, those points decide who gets paid, how much, and by what curve - all of it configurable, none of it hardcoded.

01

Contribute

Block by block, an author produces a block and is credited for it.

02

Earn Points

Contribution accrues in BlockPointsStore, incremented automatically via on_initialize.

03

Calculate Payout

The inflation model - Constant, Halving, or Sigmoid Payout - sizes the total pool for the session.

04

Determine Payees

The reward model - SharesPay or EqualPay - decides how that pool splits between authors.

05

Distribute Rewards

RewardAuthors settles the payout through Config::Asset and the role adapter’s CompensateRoles.

06

Clear Points

Session-scoped storage - nothing carries over once the session settles.

Accountability

Rewards Wait. Penalties Don't.

Good participation is rewarded once, at the close of every session. Misbehavior is penalized the moment it’s reported - accountability doesn’t wait for a schedule.

Scheduled · Once Per Session

Rewards

Settled once, at the close of every session - predictable, calculated, tied to the settlement step in the main cycle.

Reactive · Anytime

Penalties

Triggered the moment an offence is reported - reactive, unscheduled, independent of session boundaries entirely.

01

Offence Reported

pallet_offences reports the offence, whenever it happens - no fixed schedule.

02

Transform Severity

Config::PenaltyModel turns raw severity into an applied penalty amount.

03

Apply to Author

PenalizeAuthors reaches the author through RoleAdapter::CompensateRoles::Ratio.

04

Success / Failure

PenaltyInitiated on success, PenaltyFailed otherwise.

Penalty Models

Threshold Penalty

Clamps individual penalties to an upper bound.

Capped Penalty

Per-Author

Runtime Integration

Your Runtime. Your Rules.

Chain Manager is a set of pluggable traits and abstractions. You configure the policy, it orchestrates the lifecycle, and the result composes with the rest of your runtime - full control, without rebuilding consensus logic from scratch.

Your Runtime

Define the policy, and provide the implementations Chain Manager delegates to.

  • Implement RoleManager + CompensateRoles + FundRoles
  • Implement ElectionManager + InspectWeight
  • Choose or write a RewardModel
  • Choose or write an InflationModel
  • Choose or write a PenaltyModel
→

Chain Manager

Trait-based abstractions for the whole validator lifecycle.

  • Election Engine
  • Affidavit Model
  • Contribution Points
  • Reward System
  • Penalty System
  • Runtime Hooks
→

Your Ecosystem

Compose with the rest of your runtime and external systems.

  • Session & consensus - pallet_session
  • Block authorship - pallet_authorship
  • Offence reporting - pallet_offences
  • Your asset / treasury pallet
  • Your role / stake pallet
// Cargo.toml
pallet-chain-manager = { path = "../pallets/chain-manager", default-features = false }

// runtime configuration
impl pallet_chain_manager::Config for Runtime {
    type RoleAdapter         = pallet_authors::Pallet<Self>;
    type ElectionAdapter     = pallet_authors::FairElection<Self>;
    type Asset               = pallet_balances::Pallet<Self>;
    type RewardModel         = frame_plugins::SharesPay;
    type InflationModel      = frame_plugins::ConstantPayout;
    type PenaltyModel        = frame_plugins::ThresholdPenalty;
    type AffidavitCrypto     = pallet_chain_manager::crypto::sr25519::AffidavitCryptoSr25519;
    type MaxAffidavitWeights = ConstU32<500>;
    type NextSessionRotation = pallet_session::PeriodicSessions<Period, Offset>;
    type Points              = u64;
    type PointsAdapter       = ChainManager;
    // ...
}
